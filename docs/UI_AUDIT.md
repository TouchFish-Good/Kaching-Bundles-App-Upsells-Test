# UI Audit - Phase Two Baseline

审计日期：2026-10-13

## 结论

需求、设计规范、用户流程、组件清单和设计 token 已完整覆盖一期范围；仓库中没有此前完成的 Superpowers 需求/UI 审计记录。现有 `web/` 是 SHOPLINE React 初始模板，未实现设计文档要求的运营界面或商品页组件。因此本次将新增独立 UI 原型路由，不修改已有模板入口、后端、Function 或 Theme Extension。

## 已确认的设计约束

- 保留 TierKit 的 Ink / Canvas / Sea / Mint / Coral / Amber 视觉 token，以及“精密零售运营台”的紧凑后台方向。
- 商品折扣不与其他商品折扣叠加；店铺币种可分别允许订单、运费折扣叠加；市场金额模式保持强制排他。
- 同一 Product 的不同 Variant 可以累计数量；相同 Variant 合并数量后验证库存；不同 Product 不混计。
- 4 件在 2 / 3 / 5 阶梯中使用 3 件档作用于全部 4 件。
- 不接入真实 SHOPLINE 店铺、购物车、自动折扣 API 或 Function。

## 缺口与本次覆盖

| 文档能力 | 原仓库状态 | 本次原型覆盖 |
| --- | --- | --- |
| Dashboard 与活动概览 | 缺失 | KPI、近期活动、需要注意事项 |
| 活动管理 | 缺失 | 搜索、状态筛选、启停、删除确认、空/筛选状态 |
| 创建和编辑 | 缺失 | 控制表单、档位编辑、范围选择、排期、重叠校验和错误摘要 |
| 币种和叠加 | 缺失 | 店铺币种与市场金额的可见规则差异 |
| Widget Studio | 缺失 | 样式、设备、locale 和 fallback 预览 |
| Variant 混购 | 缺失 | 按件规格槽位、禁用组合、库存合并和金额估算 |
| 加购反馈 | 缺失 | 原型中的加载、库存阻断、成功和失败信息 |

## 仍然不在 UI 原型范围内

- 任何 SHOPLINE Admin API、Function 输入输出、数据库或购物车网络请求。
- 真实库存、真实商品、市场金额、翻译持久化和用户权限。
- Function 计算、结账优惠分摊和开发店回归测试。

## 审计发现与后续门槛

- 当前 `web/` 未配置 Tailwind；本轮为避免引入或升级构建依赖，原型使用 React + TypeScript + CSS Modules，并复用已确认的设计 token。正式开发规划时需要决定是否在完整前端中引入 Tailwind。
- 多语言清单已进入设计与原型，但完整翻译编辑和持久化属于正式开发范围。
- 通过 UI 确认前，不得将原型行为表述为平台已实现的业务能力。
