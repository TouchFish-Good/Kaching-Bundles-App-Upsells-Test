# SHOPLINE Admin REST 版本与 436 排障实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将正在使用的 SHOPLINE Admin REST 请求切到 `v20260901`，核对授权和请求契约，并以真实请求判断语言接口的 436 是否仍存在。

**Architecture:** 保留 SDK 管理的 OAuth、会话存储和刷新流程；各业务服务继续通过服务端持有的 Admin token 请求 SHOPLINE。REST 版本用一个常量统一，折扣 GraphQL 的既有 `v20260901` 路径不变。436 排障只记录非敏感元数据，不让诊断结果改变产品数据。

**Tech Stack:** Node.js、TypeScript、SHOPLINE Express SDK、`node-fetch`、`node:test`。

**Spec:** `docs/superpowers/specs/2026-10-19-admin-api-tier-actions-design.md`

## Global Constraints

- 目标 REST 版本是 `v20260901`；GraphQL 折扣适配器已使用该版本，不纳入本次 REST 改造。
- Admin 请求必须带 Bearer `Authorization` 和 `Content-Type: application/json; charset=utf-8`。
- 不记录 token、授权头、响应正文；不调用真实折扣创建，也不削弱签名、scope、刷新或 Webhook 校验。
- 436 只有在真实授权会话的请求返回成功时才可标为已解决；无会话时标为未验证。
- 保留 `main` 中其他未提交内容；仅提交本计划实际改动的文件，推送另行征求批准。

## Review Focus

- 无效 store handle：应在发起网络请求前拒绝，不能拼接到上游 URL；在 Task 1 的服务测试覆盖。
- 过期 Admin token：仍由现有会话加载器刷新，不能将前端 session token 当作 Admin token；在 Task 2 的既有和补充测试覆盖。
- 上游非 2xx：记录状态与安全 trace ID，不记录响应正文；在 Task 2 的语言服务测试覆盖。
- 不完整 scope：授权回调必须拒绝保存不完整会话；在 Task 2 的 scope 测试覆盖。
- 436 仍存在：维持前台明确错误状态，记录请求 ID，不能静默回退为店铺语言数据；在 Task 3 的手动验收覆盖。
