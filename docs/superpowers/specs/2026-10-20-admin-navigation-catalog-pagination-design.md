# SHOPLINE 管理导航与目录选择设计

日期：2026-10-20

## 目标与边界

商家在 SHOPLINE 后台通过平台导航进入多件优惠概览或翻译页，应用不再重复显示自建左侧栏、店铺名称与 Logo。创建活动页保留真实商品选择，并增加分类草稿选择；两个目录列表均按页展示，每页最多 50 项。商品搜索在中文输入法组合期间不发送请求。档位标题改为“档位#1  标题”，不显示百分比图标。

本次不开放“全部商品”或“指定商品分类”的折扣发布。`read_products` 继续用于商品与分类目录；移除专为店铺信息读取声明的 `read_store_information`。不改 SHOPLINE 折扣创建协议或 Function 规则。

## 已核对的现状与约束

- 当前页面的 `aside[aria-label="多件优惠"]` 承担店铺 Logo/名称、概览/翻译导航和语言选择。其余页面通过 URL 路由渲染：概览 `/quantity-breaks`，翻译 `/quantity-breaks/translations`，新建 `/quantity-breaks/new`，编辑 `/quantity-breaks/campaigns/:id/edit`。
- 前端 `/shop` 请求店铺名称、Logo 和数字店铺 ID；数字 ID 用于活动加载门槛、翻译页门槛和本地语言偏好键。活动、翻译和其他实际后端数据按鉴权会话的店铺 handle 隔离。生产环境 `afterAuth` 还通过 `GET /merchants/shop.json` 取得数字 ID，写入安装登记；卸载 webhook 按数字 `store_id` 匹配登记。
- 当前商品目录服务端已使用 `GET /products/products.json?limit=50` 和 `page_info`。前端“加载更多”会累积超过 50 条，且每次输入变化立即发起搜索。当前分类选项禁用；仓储允许分类草稿，但拒绝分类发布；前端草稿适配器拒绝新建分类范围。
- SHOPLINE Admin REST `v20260901` 文档确认手动分类 `GET /products/custom_collections.json`、智能分类 `GET /products/smart_collections.json` 均支持 `limit`、`title`、`page_info`，响应 `link` 提供分页。商品列表也支持这些参数及 `collection_id`。本地文档的安全方案没有明确给出每个分类端点的细粒度 scope；上线前须用已有 `read_products` 会话实测。不能凭文档缺项声明额外权限或宣布真实店已验证。
- 工作区已有未提交的页面宽度、指标布局、隧道地址和主题样式改动；本次实现必须保留，不得覆盖或混入后续提交。

## 导航与界面

移除应用自建 aside、遮罩、移动抽屉按钮及相关状态。主内容占满可用嵌入宽度；页面标题和操作区继续沿用现有 Shopify 参考视觉，不新造导航。向商家提供 SHOPLINE 应用导航配置路径：概览 `/quantity-breaks`、翻译 `/quantity-breaks/translations`；真实后台菜单的创建与生效需要在 SHOPLINE 配置中验证，本地 URL 路由测试不能替代。保留直达新建、编辑及浏览器后退功能。

应用语言选择移到页头操作区：概览页紧邻“创建活动”左侧；空列表仍须显示“创建活动”主操作以保证位置稳定。编辑和翻译页也在页头操作按钮左侧显示同一语言选择，避免离开概览后无法切换。移动视口允许页头换行，但语言选择和主操作不得重叠或溢出。所选语言继续按已鉴权店铺身份在本地保存。

档位面板标题使用当前后台语言的“档位”译文、序号及档位标签，格式为“档位#1  Single”；中文示例为“档位#1  标题”。标题保持随档位名称即时更新。仅档位面板隐藏 `BadgePercent` 图标，其他设置面板图标保持原样。

## 店铺身份与权限迁移

前端 `/shop` 改为只返回从已鉴权会话取得的店铺 handle 作为页面隔离键，不再请求或返回店铺名称、Logo，也不再阻塞页面等待 `GET /merchants/shop.json`。语言偏好使用 handle 键；若现有数字 ID 偏好可安全迁移则迁移一次，否则使用当前语言默认值，不读取其他店铺键。前端的活动与翻译加载仍须等待鉴权成功，不能由 URL 参数决定租户。

移除 manifest、必需 scope 校验及示例配置中的 `read_store_information`。保留 `read_products` 和其他现有业务权限，确保旧的已授权会话在 scope 缩减期间仍可使用；配置变更是否需要重新授权由 SHOPLINE 实测确认。

安装登记不再在 `afterAuth` 使用店铺信息 REST 查询。由经 SDK 验签的安装 webhook 的 `store_id`，结合其已鉴权 session handle，写入稳定店铺 ID 与 handle；重复事件按现有登记幂等逻辑处理。若安装事件缺少可信 handle 或数字 ID，则只记录受限诊断并保持待同步，不使用 handle 伪造数字 ID。现有登记记录保留，卸载 webhook 继续按真实 `store_id` 匹配。发布前需验证 SHOPLINE 实际安装事件包含所需 session/字段，若不满足则保留登记迁移为阻断项，不能静默降低登记正确性。

## 商品和分类选择

商品选择器改为单页替换显示。服务端保持 `limit=50`；前端保存已访问页的 `page_info` 历史，提供上一页/下一页，不能把多页结果累加到同一个列表。跨页已选 Product ID 保留，并在独立已选区展示；重新打开草稿时按 ID 加载标题。查询改变时回到第一页，旧请求取消；错误状态保留当前选择并支持重试。无下一页时禁用下一页，不推测总页数。

分类选择器在同一商品范围面板启用“指定商品分类”。手动分类和智能分类作为两个明确选项分别分页，每页最多 50 个分类；两类共用已选 `collectionIds`，标题仅供展示，持久化使用真实 ID。后端新增只读分类代理，复用现有鉴权、Admin REST 版本、请求头、请求 ID 和安全 trace 格式；只接受分类类型、标题、分类 ID 及 `page_info`，不接受前端指定的任意 URL。根据响应 `link` 提取游标，限制游标和结果大小，检测重复游标。重新打开草稿时以 SHOPLINE `GET /products/collections/{collection_id}.json` 按 ID 恢复分类标题与类型。分类搜索、翻页与选中商品使用一致的交互状态。选中分类后可查看其中的商品预览，调用 `GET /products/collections/{collection_id}/products.json`，每页最多 50 个商品并提供上一页/下一页；该预览不改变保存的分类范围，也不声称分类折扣已发布。

分类范围可保存和重新编辑草稿；前端适配器保存唯一真实分类 ID，避免页面切换后丢失。发布按钮在分类范围下禁用并说明尚不可发布；服务端原有分类发布 409 阻断保留。重叠检查显示“未验证”，不声称已展开分类成员或可安全发布。

## 搜索节流与失败处理

商品及分类输入在 `compositionstart` 到 `compositionend` 之间只更新文本，不发请求；组合结束后等待 300 毫秒，取最终字符串发一次请求。普通键盘输入也使用 300 毫秒等待。清空搜索应返回第一页；快速连续输入只提交最后一次查询。每次新查询或翻页取消/忽略旧响应，避免旧页覆盖新结果。不会在拼音 `z`、`zu`、`zui` 阶段向目录发送请求。

目录上游非 2xx、无效 JSON、缺少列表或不可解析分页头均返回明确错误，不输出 token、完整响应或游标。界面显示可重试状态，不清除已选内容。分类列表无法访问时仅分类选择不可用，不影响指定商品草稿。权限缺失显示授权错误，不伪装成空列表。

## 验收

先写失败测试，再实现。自动化覆盖：两个直达路径和历史导航、aside 完全移除、语言选择位置与偏好隔离、scope 缩减和安装/卸载登记、商品与两类分类各 50 条分页及跨页选择、分类草稿往返和发布阻断、中文输入法组合与普通快速输入、取消旧响应、档位标题与图标。运行前后端测试、类型检查与构建，核对变更清单和秘密信息。

按项目规则留存 Shopify 参考截图与本地桌面/移动截图，实际访问页面并操作分页、语言、草稿和导航；仅自动化通过的项目不得标记为真实店验收。SHOPLINE 后台导航配置、分类端点授权、安装 webhook 字段、真实店草稿和发布状态均须在授权店铺实测后标记通过。完成页面时更新 `docs/APP_PROGRESS.md`，并继续检查下一个未验收页面。每个变更集经用户审阅批准后才允许提交和推送。
