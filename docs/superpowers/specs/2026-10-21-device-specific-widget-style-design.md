# PC 与移动端独立样式设计

日期：2026-10-21

## 目标与范围

商家在活动编辑页的“样式”区域，像现有实时预览一样用 PC / 移动端分段按钮切换。当前设备的全部样式选项可单独编辑，包括布局、卡片、颜色、字体、标签位置、规格展示和价格展示。切换设备不丢失未保存的修改；预览与样式区域始终指向同一设备，立即展示该设备的设置。活动名称、商品范围、档位、折扣计算、时间和翻译仍由两端共用，不复制业务规则。

## 配置与旧活动

沿用现有 `widget.version: 1` 与根级样式字段作为 PC 配置，增加可选 `widget.mobile`，包含与 PC 相同的样式字段但不再嵌套 `version` 或 `mobile`。两端都是完整配置，不以移动端差异补丁合并，避免编辑某端时意外改变另一端。服务端分别严格校验两端字段、范围与颜色；未知字段和无效颜色仍阻止保存。

旧活动没有 `widget.mobile` 时，编辑器与前台都以 PC 配置的深拷贝作为移动端的初始效果。商家第一次修改移动端设置后保存，写入完整 `widget.mobile`；未修改移动端的旧活动仍按原配置工作。编辑器不因打开或切换设备就写回活动。保存再打开后，两端设置及当前活动修订号按现有持久化流程保持一致。

## 编辑器交互

“样式”内容顶部添加与预览一致的 PC / 移动端分段按钮，并复用编辑页已有的 `activePreviewDevice` 状态。点击任一处的设备按钮，同步更新另一处的选中状态、所有样式表单值和实时预览。样式表单只修改当前设备的配置；颜色选择器、滑杆、字体输入、布局单选和规格设置均遵循此规则。切换时关闭悬浮颜色选择器，避免旧设备的弹层覆盖新设备表单。

预览继续在 PC / 手机外壳之间切换，并把当前设备配置传给 `StorefrontWidget`。两个设备独立校验 HEX 颜色；若未选中的设备有无效值，保存时切换到有错设备、展开样式区域并聚焦该颜色字段，避免隐藏错误。当前设备切换不改变已选商品、档位或编辑器外的活动内容。

## 前台应用

公开活动 API 继续返回整个 `widget`，不新增接口或 SHOPLINE 权限。主题组件在视口宽度小于 768px 时采用移动端配置，否则采用 PC 配置；无移动端配置时采用 PC 配置。现有主题与预览中横排/网格布局的单列断点统一到 768px，使移动端设置与手机预览一致。

主题首次挂载和跨越断点时应用对应设备的 CSS 变量、布局、标签位置与规格展示设置。断点切换不得重新请求活动或丢失当前档位；已有规格选择在新设备规则下仍有效时保留。若新设备禁止混搭而原选择包含多个 Variant，则以第一个有效已选 Variant 统一各槽位；若该 Variant 已不可售，按新设备的默认选择规则重新选择或保留未选状态，禁止提交无效组合。相同设备内的普通窗口缩放继续由 CSS 响应式规则处理。商品数量、折扣、可售性与加购请求均沿用现有规则。

## 验收与边界

- 单元与交互测试：旧活动默认两端一致；分别修改、保存、重载后两端互不覆盖；两个设备的无效值都被校验；切换按钮同步表单和预览；主题在断点两侧读取正确配置并保留已选档位/规格。
- 视觉检查：保留 PC 与 390px 本地截图，检查四种布局、长标签、颜色弹层、分段按钮选中与焦点状态，无文字重叠或横向溢出；在认证店铺中复核已保存活动的前台实际效果。无法实际访问的页面在 `docs/APP_PROGRESS.md` 标为未验收。
- 本次只改变活动组件外观和选择器展示，不改变 Discount Function input、活动发布流程或结账折扣。现有工作区中尚未提交的分类发布实现和临时隧道地址须独立审查，不因本设计自动推送。
