# 折扣名称与商品范围冲突明细设计

## 目标

将后台活动名称和 SHOPLINE 购物车/结账中显示的折扣名称分离；在编辑器中显示可追溯到商品的范围冲突详情。

## 数据模型与兼容性

- `CampaignDraft.name` 继续表示“名称（仅您可见）”。它用于后台活动列表、搜索、详情和冲突信息。
- 新增 `CampaignDraft.discountName`，表示“折扣名称（显示在购物车/结账页面）”。它是创建及更新 SHOPLINE 自动折扣时唯一传给 `title` 的字段。
- `discountName` 为新建和保存活动时的必填字段。新建表单使用与内部名称相同的初始值，商家可分别修改两个值。
- 旧 JSON 活动没有 `discountName` 时，读取、校验和 SHOPLINE 更新均回退到既有 `name`。这样旧活动不会因本次升级改变已显示的 SHOPLINE 标题；下次保存时会持久化回填值。
- 已有活动的 `name` 原样保留，不做批量改名或数据迁移。

## Worker 合同

- `buildDiscountRule` 保持与显示名称无关；Function 规则和计算结果不受本改动影响。
- `discountInput` 使用 `campaign.discountName` 作为 SHOPLINE `title`，防止内部运营名称泄漏到购物车与结账页。
- 新增或扩展覆盖范围检查接口，返回确定性的冲突行：活动 ID、活动名称、商品/分类 ID、显示名称和范围类型。指定商品冲突必须通过店铺 Admin API 解析真实商品标题；解析失败时保留 ID 作为可诊断的回退值。
- 启用与批量启用复用同一冲突描述逻辑，避免编辑器显示结果与服务端阻止规则不一致。

## 编辑器与列表

- 设置面板先显示“名称（仅您可见）”，再显示“折扣名称（显示在购物车/结账页面）”。两个输入各自有标签、说明、必填校验和稳定的错误定位 ID。
- “检查商品覆盖范围”结果在 `conflict` 状态下将 `.overlapClear` 应用为淡红提示背景，并显示标题“商品范围冲突”。
- 冲突详情表格按一行一个重叠对象呈现：`活动名称 | 商品名`。同一活动命中多个商品时显示多行；React key 使用活动 ID 与对象 ID 的组合。
- 无冲突状态保留既有绿色成功外观；检查中、未验证及分类优先级说明保持现有行为。
- 折扣列表在“活动”列右侧增加“折扣名称”列。桌面表格与移动卡片都显示该字段；缺失旧字段按内部名称展示。

## 本地化与可访问性

- 所有后台支持语言增加内部名称、折扣名称、字段说明、错误、冲突标题、冲突表头和列表表头的翻译键。
- 商品名称、分类名称和商家输入的两个名称属于数据，不由应用翻译。
- 冲突区域继续使用 `aria-live=polite`，表格提供语义化 `thead`、`th` 和 `scope="col"`；颜色不作为冲突状态的唯一载体。
- 小屏保持纵向阅读：冲突表格在容器内横向滚动或遵循当前卡片布局，不能撑破编辑器宽度。

## 验证

- Worker 单元测试：旧活动回退、新活动校验、创建/更新请求使用 `discountName`、范围冲突返回商品标题。
- 前端测试：适配器回退、编辑器双输入及保存 payload、冲突明细表、淡红冲突态、列表列顺序及移动展示。
- 翻译测试：每个后台 locale 都拥有新增键且占位符一致。
- 生产构建、Worker 测试、前端完整测试和 `git diff --check` 作为合入前检查。

## 非目标

- 不翻译 SHOPLINE 折扣标题本身；它是商家配置的一个显示值。
- 不改变 Function 优惠计算、商品范围冲突判定规则或第三方优惠检测能力。
