# 阶梯优惠、多市场金额与翻译设计规格

状态：待商家审阅。本规格不授权实现代码或修改真实店铺数据。

## 目标与范围

让现有 Quantity Breaks 应用对商家更准确、易懂：清理重复导航和操作，按所选档位数量展示每件商品的独立规格选择器，分别配置每档折扣类型与数值，支持市场专属金额，并且只为当前店铺启用的前台语言编辑翻译。保留现有活动流程及以 Shopify 参考页面为基准的视觉方向。本地原型不能被描述为已经完成 SHOPLINE 正式接入。

代码检查确认：`StorefrontWidget.tsx` 中的 `firstSlots` 固定只有五项，通过截取该数组扩展选择器无法产生第六项；翻译页使用静态的 11 种语言和仅保存在草稿状态的数据；Overview 中有两个「Create campaign」入口。这些是当前实现问题，并非平台限制。

## 导航与 Overview

- 移除冗余的 `Apps / Bundle deals` 面包屑文字，以及侧边栏底部的 `Bundle deals`。保留实际应用导航；在有活动的 Overview 页面只显示一个主要「Create campaign」操作。空状态仍须提供创建入口，但同一视口不重复显示两个同等操作。
- 全应用使用真实、准确的产品文案。已连接店铺时显示数据支持的店铺、商品与指标；未连接或无数据时显示明确的加载、空、不可用或演示状态。不得把虚构活动数、销售额等当作商家真实数据。
- 相关界面以已观察到的 Kaching 页面布局和状态为参考。UI UX Pro Max 用于一致性及可访问性检查，Frontend Design 指导实现，均不代替实际参考页面。

## 阶梯编辑器与前台规格选择

- 每个阶梯包含正整数 `quantity`、可编辑的标题/副标题/标签文案、`discountType`（`none`、`percentage`、`fixed_amount`、`fixed_price`），以及按类型显示的 `discountValue`。`none` 表示原价，不显示并清除数值输入；百分比类型输入百分数；`fixed_amount` 是每件固定减免；`fixed_price` 是每件固定售价。
- 规格选择器的数量始终等于当前档位的数量，不能固定最多五件。增加数量时保留已有的有效选择，只初始化新增位置；减少数量时保留仍在范围内的位置。不存在或售罄的规格组合不可选；重复选择同一 SKU 时合并数量进行库存校验和购物车提交。
- 预览价格必须按实际选中的全部规格计算，不得截取固定样例数组。测试数量 1、5、6，以及更大的商家自定义数量；核验价格预览与加购数据均覆盖每一件。最终结账折扣以 SHOPLINE 实际计算为准。

## 金额类折扣的多市场配置

- `fixed_amount` 与 `fixed_price` 均显示以店铺币种计价的基础金额，以及多市场设置。通过已核实的 Admin 市场接口 `GET /markets.json` 获取当前店铺市场、启用状态、市场 ID 和币种，并处理分页；不得仅根据市场名称推测币种。金额按对应币种精度存储为最小货币单位。
- 每个市场显示名称、币种及折扣形式下拉框：`auto_convert`（默认，按店铺货币和当前汇率由平台自动换算）或 `specified_amount`（指定金额）。选中指定金额后，才显示该市场币种的金额输入框并校验。自动换算模式保存的是选择，不保存某一时刻的汇率快照；结账时应用不自行套用猜测的汇率。
- Function 按 `localization.marketId` 识别买家当前市场。该市场没有指定金额时，输出店铺币种折扣值，由 SHOPLINE 执行当前换算。有指定金额时，同一次 Function 调用的所有适用输出都必须使用市场币种，不得混用两种币种模式。百分比可根据市场展示价计算金额；但同次调用中的自动换算固定金额需要平台权威的换算结果或汇率契约。商品的「市场展示价 ÷ 店铺价格」不可靠，因为市场可能设置独立定价。在该契约和混合配置经开发店验证前，阻止发布可能在同一市场产生两种输出模式的配置。
- `fixed_price` 不是 Function 原生输出类型，须根据适用规格的当前原始单价转为每条购物车行的减免金额，并限制在 `[0, 单价]` 范围内，同时正确处理行数量。指定市场固定售价应与该规格实际的市场展示单价比较，包含市场独立定价的影响。
- 已有资料将市场币种 `presentmentFixedAmount` 折扣标记为不能与其他折扣叠加。市场覆盖值旁须明确提示这一影响；可能使用市场覆盖值的活动不能展示与之矛盾的叠加选项。该限制仍须在开发店复核。无法确定市场身份、币种、平台能力或统一输出模式时，应给出明确错误并阻止发布，不能静默使用错误金额。UI 原型阶段不调用真实折扣创建接口。

## 翻译页面

- 从 `GET /store/languages.json` 获取店铺默认语言 `default_language` 和当前使用的前台语言 `supported_languages`。商家的语言下拉框只显示这些语言。请求失败时显示错误和重试；本地未连接店铺时明确标注演示数据，不将样例语言冒充为店铺语言。
- 参考已观察到的原版结构：左列只读原始文案，右列编辑当前选中前台语言的译文，按组件中实际出现的位置分组。每组标明该文字出现的前台位置，使商家能分辨编辑结果；原文和译文逐行对应，不显示虚构的完成率。
- 每个分组随内容增长，但最多占用当前视口的可用高度，超出后在分组内部滚动。保留键盘操作、可见标签与焦点、未保存修改提示、保存成功/失败反馈，以及有未保存修改时切换语言的处理。前台文案语言和后台管理界面语言是两项不同设置。
- 翻译键必须对应 Quantity Breaks 前台组件实际渲染的文本。商家逐档自定义的标题、副标题和标签属于档位内容，不混入通用系统翻译。编辑译文时始终保留原文供对照。

## 数据边界与验收

- Admin 接口请求必须通过现有服务端与鉴权边界，不在未鉴权的浏览器代码中直接调用。市场和语言缓存须规定刷新策略；执行刷新后应能看到店铺新启用的市场和语言。原型可使用明确标识的样例数据，但正式持久化和 Function 行为需要单独实现与测试。
- 单元测试覆盖超过五件的阶梯、切换档位后的选择保留、不同 SKU 价格与库存、折扣类型校验、币种精度、市场模式选择、市场或币种缺失，以及只展示店铺支持的语言。界面测试覆盖重复创建入口清理、动态字段、市场金额输入、翻译原文与译文对齐、滚动、加载/错误/空状态和移动端布局。
- 在标记为 `VERIFIED` 前，必须在开发店验证自动换算、指定金额、不同规格和市场定价下的固定售价、不可叠加规则，以及购物车和结账金额。构建成功或模拟预览不能代替这些验证。
