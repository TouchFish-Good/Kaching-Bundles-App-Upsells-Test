# Quantity Breaks 正式接入与档位排序设计

状态：待商家审阅。本文定义实现边界，不代表已连接店铺或已验证结账。

## 目标与已确认规则

在现有 React/Express/Go Function/Theme App Extension 工程内，完成一期 Quantity Breaks 从商家配置到商品页、购物车及结账的闭环。商家可拖拽调整档位的**展示顺序**；优惠命中仍按数量阈值选择最高已达档，与展示顺序无关。例如展示顺序为 5、2、3，购买 4 件仍按 3 件档给全部 4 件优惠。每个活动的商品范围不得与其他启用或即将生效的本应用活动重叠。同一 Product 的不同 Variant 合并计数，不跨 Product 计数。

当前代码证据：`CampaignEditor.tsx` 的 `GripVertical` 仅用于绘制；活动主要是前端内存状态；`main.go` 返回空 `discounts`；Theme App Block 和 JS 仍是模板内容。已实现的市场、语言和翻译接口保留，不把这些进度描述为全应用完成。

## 工作拆分与依赖

1. 商家端档位排序和可访问替代操作。此项可独立验证，但保存格式必须与后续活动模型兼容。
2. 活动持久化和发布编排。先确保 SHOPLINE 侧 Function 规则有可信来源，再接入折扣 API。没有该步骤，Function 无法消费商家配置。
3. Go Function。由平台输入读取折扣节点规则与购物车行，计算同 Product 跨 Variant 阶梯，并输出多个 `CartLineTarget`。
4. Theme App Block。通过已发布活动与商品目录数据渲染真实选择器，按 Variant ID 合并后使用购物车原子批量加购接口。
5. 开发店联调和回归。购物车、结账、市场切换、库存失败及折扣叠加结果达到验收标准后，才把对应模块标为 VERIFIED。

每步更新 `APP_PROGRESS.md` 和差异报告。其他优惠模板、计费、分析及真实 Shopify 页面复制不并入这个一期闭环。

## 档位排序交互

档位行以稳定 `tierId` 标识，不能继续以数组索引充当 React key 或金额输入草稿键。拖拽柄是独立按钮，指针长按或抓取后显示目标位置；仅在有效落点完成重排，取消拖动或拖出列表不修改数据。收起的档位面板保持原展开状态，推荐档跟随其 `tierId`，金额、市场覆盖和错误信息也跟随同一 ID。

每个档位提供键盘可用的“上移/下移”操作与可读的当前位置反馈，触屏至少可用该替代操作。拖动时不能意外触发折叠或修改输入值。实时预览采用商家指定的展示顺序；计算引擎始终独立地按 `quantity` 查找最高已达档。持久化 `displayOrder`，迁移旧活动时按原数组顺序赋值。重复、零或非整数数量继续阻止保存。

## 活动数据与服务边界

服务端以已鉴权 shop 标识隔离数据。持久化 `Campaign` 的 ID、状态、时间、时区、商品范围、排除项、档位（含稳定 ID、展示顺序、折扣类型/整数金额、推荐标记、文案和市场覆盖）、叠加选项、Widget 配置、版本号及 SHOPLINE 折扣规则 ID。敏感会话和 access token 不进入前端响应或 Function metafield。

新增经过鉴权的列表、读取、创建、更新、启停和删除接口。服务端再次校验数量、金额、时间、市场币种、范围交集与版本号；不能只信任浏览器校验。活动保存和平台规则发布分为可重试的状态：本地草稿先落库，平台创建/更新成功并记录规则 ID 后才标记可发布；失败保留草稿和明确错误，不把 UI 标为 Active。重复提交按本地 ID/规则 ID 幂等处理。编辑与删除也要处理平台成功、本地失败及反向失败的补偿/重试，不能留下无法识别的生效规则。

商品范围通过 SHOPLINE 商品与分类接口获取实际 ID 和成员；排除项优先。发布前和启用前展开当前成员并与其他 Active/Scheduled 活动检查交集。分类成员变化需要发布前复查；后续变化通过可验证的事件或定期同步处理，在获得该契约前不得承诺实时无冲突。`all products` 与任何其他启用活动冲突。Function 只信任已发布规则中的范围快照/可表达的运行时范围判断，不读取应用数据库。

## Function 规则与金额计算

规则 JSON 放在 SHOPLINE 自动 Function 折扣支持的 `sale` namespace metafield 中，带 schema 版本、活动 ID、商品范围/排除、有效时间、档位和市场设置。发布前核实官方 mutation/REST 端点、metafield 大小限制、Function ID 与 `combinesWith` 字段；未核实的字段不得写入生产请求。规则过大或平台拒绝时发布失败，不截断规则。

`input.graphql` 只请求已由工程 schema 与 Function 资料确认且计算必需的字段：折扣节点 ID/metafields、`cart.lines` 的行 ID/数量/Variant 所属 Product ID/价格，以及当前 `marketId` 和市场展示价。Function 逐个折扣节点解析并验证版本；按 Product ID 聚合合格行数量，选择数量不大于总件数的最大阈值；对该 Product 的所有命中行生成 `CartLineTarget`。无效规则、缺失价格/币种或不能确定的市场不输出折扣，并记录开发环境可诊断信息，不猜测金额。

计算全程使用最小货币单位整数和整数基点。`none` 不输出折扣；`percentage`、`fixed_amount`、`fixed_price` 均计算每个 Variant 的每件减免，限制在 `[0, 实际单价]`。固定售价按每条行的实际 Variant 单价转成减免。每行输出数量与输入行匹配，`appliesToEachItem` 一致。单价不同的 Variant 分别计算并分别返回行级金额。舍入规则先在纯计算测试中固定，再用开发店 1、2、3、4、5、6 件及不同单价核对平台最终结果；不把预览结果视为结账权威值。

默认店铺币种使用 `fixedAmount`。市场指定金额使用 `presentmentFixedAmount`，输出币种取当前市场商品价格的币种并核对配置；命中行不能与其他优惠叠加。Function 资料规定同一次运行结果不能混用店铺币种和市场币种 Value，因此发布校验必须横跨所有可能同时生效的活动：在同一市场产生指定金额的配置，与会输出店铺币种金额的活动不可同时启用。百分比在该市场也要按市场价转为同币种的行级减免。自动换算不自行用商品价格比值推汇率；由平台转换店铺币种金额。无法证明整次运行币种模式一致时阻止发布。

店铺币种模式下商品折扣组合保持关闭；订单、运费叠加选择映射到经过官方 schema 核实的自动 Function 折扣创建/更新字段。市场指定金额的叠加控件锁定关闭。每个活动对应的平台规则数量与单店/Function 上限在创建前检查。

## Theme App Block 与购物车

App Block 位于商品页，可由商家在主题编辑器添加。块的前端脚本根据当前商品 ID、locale 和店铺上下文加载已发布且当前有效的活动及真实 Product/Variant 数据；公开接口只返回展示所需配置，不返回管理数据或 token。商品数据字段、主题运行时变量、跨域与缓存策略须先在目标 OS 3.0 主题中确认，再固化请求契约。无匹配活动、活动未生效或数据不完整时不展示可购买的优惠。

选中数量档后渲染相同数量的独立 Variant 槽位，沿用已确认的 Dropdown、纯文本、色板和款式图样式。每个槽位只允许存在且可售的组合；同一 Variant 多次选择时按合并数量校验库存。切换档位保留隐藏槽位草稿，恢复时重新核验。预估价随各 Variant 实际价格变化，明确以 SHOPLINE 购物车/结账为准。加购前再次核验数量和库存，按 Variant ID 合并为 `items: [{ id, quantity }]`，一次 `POST /cart/add`；请求失败保留选择并显示错误，不宣称成功。对网络超时等无法判断是否已加购的情况，先读取购物车确认结果，避免用户重试造成重复加购。

Theme Extension 仅负责商品页呈现与购物车操作，不修改结账价格。后台、Function、主题共享有版本的规则契约与测试样例，但 Go Function 不在运行时请求应用服务器。

## 验证与待确认合同

- 单元测试：拖拽/键盘排序和草稿保留；范围重叠；金额精度；同 Product 多 Variant 计数；原价和每种折扣；4 件最高已达档；多市场统一币种；坏规则安全失败。
- 服务端测试：按店铺隔离、CRUD、版本冲突、发布/删除重试、SHOPLINE API 错误、Function 规则同步。
- 浏览器测试：创建/编辑/排序/保存刷新、桌面与手机、输入/拖拽冲突、Variant 缺货、原子加购失败及可访问反馈。
- 开发店测试：安装 App Block、真实商品和 Variant、购物车与结账 1/2/3/4/5/6 件、不同 SKU 价格、市场指定/自动换算、叠加限制和库存失败。真实店铺写入仅在明确的开发测试范围内执行。

仍须通过官方文档和开发店核实：自动 Function 折扣完整创建/更新/删除契约及 metafield 限额；商品/分类和主题商品数据接口；市场自动换算与统一输出模式的实际结果；购物车超时后的幂等确认方式。合作伙伴后台本轮浏览器连接失败，未据此推断线上配置。
