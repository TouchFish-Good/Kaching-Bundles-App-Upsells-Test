# 活动批量操作与折扣叠加设计

## 目标

优化 Quantity Breaks 活动管理与创建体验：列表中的启用、暂停、删除统一通过多选操作完成；所有批量破坏性或状态变更操作使用 SHOPLINE App Bridge 二次确认；创建或更新时，商家能够明确配置与订单、商品、运费折扣的叠加意图，并正确理解指定市场金额的运行时限制。

本设计不改变 Quantity Breaks Function 的优惠计算，也不改变指定市场金额使用 `presentmentFixedAmount` 的规则。

## 已确认的平台能力

SHOPLINE 官方 `DiscountCombinesWithInput` 文档确认 `DiscountAutomaticAppInput.combinesWith` 支持以下三个布尔字段：

- `orderDiscounts`
- `productDiscounts`
- `shippingDiscounts`

因此活动的三项叠加意图均可同步到 SHOPLINE Function 自动折扣。Worker 的 REST 适配器使用等价的 `combines_with_modes` 字段，必须将三类 code 和 automatic 对应项保持一致。

## 数据契约与发布映射

活动的 `combinesWith` 从两个字段扩展为：

```ts
{
  orderDiscounts: boolean;
  productDiscounts: boolean;
  shippingDiscounts: boolean;
}
```

新建活动三项默认均为 `false`。旧活动读取时缺少 `productDiscounts` 按 `false` 兼容；保存后写入完整对象。

Worker 和 legacy app 的发布适配器按商家选择上传：

| 活动配置 | SHOPLINE `combines_with_modes` |
| --- | --- |
| 订单折扣 | `order_discount_code`、`order_automatic_discount` |
| 商品折扣 | `product_discount_code`、`product_automatic_discount` |
| 运费折扣 | `shipping_discount_code`、`shipping_automatic_discount` |

指定市场金额**不得**清空、锁定或改写这三项叠加意图。活动创建、更新和重新发布仍上传商家选定的值。

## 指定市场金额的运行时限制

适用范围仅为以下折扣类型的 `specified_amount` 市场覆盖：

- 每件固定价格
- 每件固定减免
- 整单固定价格
- 整单固定减免

Function 在命中该市场覆盖时返回市场币种金额字段。该行在平台运行时不能与其他活动叠加，即使活动的总体 `combinesWith` 声明了可叠加。此限制针对实际命中的商品行和市场，而不是整个活动；因此配置仍需要原样上传。

“设置 - 折扣叠加”区域的行为如下：

1. 商家始终可切换订单、商品、运费三项开关。
2. 当至少一项开关为开启，且存在上述指定市场金额档位时，显示说明和表格。
3. 说明使用当前已开启的类型名称：`因当前档位设置了指定市场金额，以下档位在指定市场不与主站（商品、订单）折扣叠加。` 括号中的“商品、订单”按当前实际开启的叠加类型动态替换，可为商品、订单、运费中的一项、两项或三项。
4. 表头为“档位名称”“市场”；同一档位的多个市场以 `、` 分隔。
5. 只列出实际配置了指定市场金额的固定类型档位。百分比档位和 `auto_convert` 覆盖不出现。
6. 未开启任何叠加类型时，不显示该说明或表格。

示例：启用商品、订单折扣叠加；`two` 为 10% 折扣；`three` 为每件固定减免，且日本、韩国采用指定市场金额。提示表只显示 `three | 日本、韩国`。

## 创建与更新体验

“设置”折叠区在创建和编辑页面均默认展开。订单、商品、运费折扣开关默认关闭。

点击创建、保存草稿或发布时，名称和开始时间均为必填：

1. 缺少活动名称时展开包含名称字段的折叠区，聚焦名称输入框。
2. 缺少开始时间时展开包含排期字段的折叠区，聚焦开始时间输入框。
3. 使用 App Bridge `Message` 显示本地化错误，而非无反馈返回。
4. 非嵌入式开发环境沿用现有 toast 回退，但内容和字段校验一致。

后端继续将 `startsAt` 作为强制校验，不能仅依赖前端。

## 活动列表与批量操作

单条活动不再提供暂停、启用或删除按钮。活动名称和编辑入口保留；选择一项或多项后才显示批量工具栏。

批量工具栏仅包含：

- 启用
- 暂停
- 删除
- 清除选择

不再显示或调用“结束活动”。

每次点击启用、暂停、删除都先打开 App Bridge 确认：

| 操作 | 类型 | 确认语义 |
| --- | --- | --- |
| 启用 | `confirm` | 说明将启用所选活动。 |
| 暂停 | `warn` | 说明所选活动将停止在店铺中生效。 |
| 删除 | `danger` | 说明所选活动会被永久删除。 |

确认后逐项执行已有的状态或删除 API，并刷新列表。删除仍先结束已发布平台折扣，再删除本地活动。部分失败时保留已完成结果并给出可重试的本地化错误。

## 列表中的叠加展示

“可叠加折扣”单元格每种已开启类型占独立一行：

```text
订单折扣
商品折扣
运费折扣
```

没有任何开启项时显示本地化的“无”。桌面表格与移动卡片采用同一映射。

## 活动列表的列宽与多语言布局

活动表格目前存在两组重叠的 CSS 列宽规则，后声明的规则把状态和开始时间过度放大，同时压缩结束时间，导致较窄桌面出现状态、档位等文本视觉重叠。本轮改用一组唯一、稳定的列定义，不再依赖互相覆盖的 `nth-child` 宽度规则。

桌面表格保留八列并使用语义化 `colgroup`：勾选列固定 48px；活动、商品、档位、状态、开始时间、结束时间、可叠加折扣依次使用受约束比例列。活动列从当前过大的固定表现收窄，日期列获得均衡的最小可读空间，可叠加折扣列保留容纳逐行内容的宽度。表格最小宽度调整为与八列内容相符的紧凑值，而不是当前的 1160px。

| 视口 | 呈现方式 |
| --- | --- |
| 1024px 及以上 | 八列表格，固定列策略、列标题和单元格居中。 |
| 768px 至 1023px | 保持同一稳定表格，外层仅在必要时横向滚动；不压缩文本或让列内容相互覆盖。 |
| 767px 及以下 | 沿用现有活动卡片，不展示桌面表格。 |

列标题和单元格允许正常换行并使用 `overflow-wrap:anywhere`，不使用会截断本地化语言的强制 `nowrap`。单元格采取顶部/中部稳定对齐；状态徽章、日期、档位和可叠加项均在各自列内居中。活动名称保持可点击、可键盘聚焦，长名称在自己的列内换行，不挤占相邻列。

所有列标题、分页、选择框的可访问名称、批量工具栏以及可叠加类型都必须经后台翻译字典读取。不得保留 `Order discounts`、`Shipping discounts`、`None`、`selected`、`Rows per page`、`Previous`、`Next` 等硬编码英文；11 种语言的 key 集必须一致。

## 国际化与无障碍

所有新增或变更的后台文案写入 `admin-workspace-messages.ts` 或 `campaign-editor-messages.ts`，并在 11 个后台语言中保留完全相同的 key 集：`en`、`fr`、`de`、`es`、`it`、`nl`、`sv`、`tr`、`pt-BR`、`zh-Hans`、`zh-Hant`。

包括批量按钮、确认标题和正文、成功/失败反馈、缺失名称/开始时间提示、三种叠加类型、指定市场金额说明与表格列名。确认弹窗保留操作名称和选中数量，便于屏幕阅读器理解影响范围。

## 测试与验收

测试覆盖以下内容：

1. 前端活动适配器正确向后兼容旧活动，并保存 `productDiscounts`。
2. Worker 和 legacy 发布适配器将三类叠加值逐项传给 SHOPLINE；存在指定市场金额时也不改写这些值。
3. 活动验证要求三个布尔叠加字段，并兼容旧的持久化记录迁移。
4. 编辑器新建默认关闭三项叠加；设置区默认展开；缺少名称或开始时间会展开、聚焦并显示本地化反馈。
5. 指定市场金额提示只列合格固定类型、聚合市场名称、根据当前开启项生成文案。
6. 列表没有单条状态/删除操作；批量启用、暂停、删除都必须经 `BridgeConfirmation` 后调用 API；“结束活动”不可达。
7. 桌面与移动列表逐行显示可叠加类型。
8. 管理端 i18n 测试验证全部 locale key 一致，并覆盖表头、分页、选择及批量操作文案。
9. 在 1440px、1024px、768px 和 390px 截图核验：表格列没有文本重叠；多语言标题可换行；移动端仍显示可扫描卡片。

完成后需要运行 Worker、app、web 的相关单测、类型检查与构建；并对列表及创建/编辑页完成桌面和移动端截图核验。
