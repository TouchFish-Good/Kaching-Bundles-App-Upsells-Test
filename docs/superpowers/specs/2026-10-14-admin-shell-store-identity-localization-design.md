# Quantity Breaks 后台外壳、店铺身份与 11 语言设计

状态：待商家审核。本文仅定义本地实现与验收范围，不授权连接或修改真实店铺数据。

## 目标与现状

商家进入 Quantity Breaks 后，应看到自己的店铺名称与 Logo，并能在应用任何页面切换后台界面语言。桌面端不显示应用内部顶部 header；移动端仍有打开侧栏的入口。移除 `Demo data` 字样，同时不能让内存示例活动被误认为真实店铺活动。

当前 `web/src/pages/quantity-breaks.tsx` 使用 `campaignData` 初始化活动，侧栏显示 `Store preview` 和通用图标，顶部显示 `Demo data`。后台 i18next 仅有英文、简体中文两份模板资源，Quantity Breaks 页面与编辑器的大部分字符串仍是直接写在组件中的英文。前台文案翻译已经有单独的店铺语言读取及存储流程，不能与后台界面语言混为一谈。主目录现有未提交的 `app/src/admin-read/`、`app/src/shopline.ts` 等修改属于已有工作，实施时保留并复用其可验证部分，不覆盖或顺带提交。

## 已核实的平台合同

SHOPLINE Admin REST `GET /merchants/shop.json` 的 v20260901 OAS 响应 `data` 包含 `id`、`name` 和 `standard_logo`；`standard_logo` 是字符串且官方示例允许空字符串。该请求使用已鉴权的店铺 Admin 会话。后台不得在浏览器调用 Admin REST 或暴露 access token。

参考：SHOPLINE AI Suite `shopline-admin-rest` 对 `/merchants/shop.json` 的搜索及 v20260901 响应详情。真实店铺的 Logo URL 形式、图片可访问性与 CSP 尚未验证；实现不能臆造图片域名或保证该字段总有图。

## 数据与接口边界

- 增加应用自己的只读 `GET /api/quantity-breaks/shop`，沿用现有 `/api/*` SHOPLINE 会话鉴权，从 `response.locals.shopline.session` 取得 handle 和 token，在服务端读取店铺信息。响应只含前端所需的店铺 ID、展示名称与经过安全检查的 Logo URL；不返回 token、邮箱等商家资料。
- 现有未提交的 `fetchShopIdentity` 已读取店铺 ID 和名称。实现时先验证它的响应解析与错误处理，再决定复用或小范围扩展 `standard_logo`；避免在同一应用中维护两套相互矛盾的店铺身份解析。
- 未鉴权返回 401；平台请求失败或无有效名称时返回明确的不可用状态，前端显示重试，不回退到虚构店名。Logo 为空、URL 不可用或图片加载失败时只用中性商店图标；店铺名称仍取已验证的真实响应。切换店铺时清除旧店身份状态，不能短暂显示另一家店的名称或 Logo。
- 删除侧栏 `Store preview`、`Not connected` 与顶部 `Demo data` 文案。移除文案不能成为继续默认展示内存活动的理由：正式嵌入式入口从鉴权活动 API 读取数据，按加载、空、失败状态显示；独立原型如仍需 fixture，必须通过显式开发预览入口隔离，不作为已连接店铺数据呈现。活动编辑 API 与当前原型模型的字段映射、保存失败保留草稿属于这项依赖的实施计划，不在设计中假称已经完成。

## 后台语言与前台翻译

后台应用 UI 固定支持 11 个语言选项：`en`、`fr`、`de`、`es`、`it`、`nl`、`sv`、`tr`、`pt-BR`、`zh-Hans`、`zh-Hant`。侧栏导航附近使用有标签的下拉框；桌面始终可见，移动端在菜单展开后可用。切换不刷新或丢弃当前编辑草稿；首次打开优先使用该店铺在此浏览器上保存的后台选择，其次使用 SHOPLINE 嵌入参数 `lang` 的受支持匹配，最后回退 `en`。持久化键按店铺 ID 或已验证 handle 隔离，不把一个店铺的选择带到另一个店铺。

后台语言覆盖共享侧栏、概览/活动列表、创建和编辑、阶梯与市场配置、Widget Studio、翻译配置页的管理控件，以及加载、空、校验、成功与错误反馈。服务端错误通过稳定错误码映射为当前语言的用户文案；未知错误提供本地化通用消息及可诊断信息，不把原始异常作为主要 UI 文案。所有语言字典必须有相同的管理键与占位符，缺失键在开发时可回退英文并被自动化检查检出，发布验收不接受大量英文残留。

前台 Widget 文案是商家可配置内容，继续由店铺启用的前台语言接口和翻译存储决定；后台语言下拉不改变店铺启用语言、不覆盖商家译文，也不改变 Function 规则或折扣金额。编辑页中的前台实时预览应有独立的前台语言选择，避免后台法语误被解释为顾客也会看到法语。金额和日期按当前显示语境格式化，币种与权威价格仍来自 SHOPLINE 店铺/市场数据。

## 布局与交互

桌面宽度下移除应用内部 `topbar`，主内容从现有侧栏右侧的页面起始位置布局，不额外增加空白带。移动端保留最小高度的菜单触发区，菜单按钮有可访问名称、可见焦点和关闭遮罩；它不恢复 `Demo data`。侧栏品牌区使用真实 Logo 的固定 34px 方形位置，图片保持比例并限制溢出；长店名可截断但须能通过 `title` 或等效可访问文本获取全名。语言下拉与导航在 360px 及以上宽度不重叠。

店铺身份加载中显示稳定占位，失败提供重试；加载成功但无 Logo 使用图标回退。切换语言后页面路由、当前编辑字段值、展开的档位和未保存状态保持不变。无障碍要求包括语言下拉标签、图片替代文本、状态通知、键盘操作与 200% 缩放下无文字遮挡。

## 验收与边界

- 服务端测试：鉴权、按店铺隔离、`name` / `standard_logo` 解析、空 Logo、无效 URL、平台失败与响应不泄露 token。
- 前端测试：11 字典键与占位符一致；语言选择、店铺切换与持久化；编辑草稿在切换语言后不丢失；管理文案与前台译文互不影响；无连接时不显示伪真实活动。
- 浏览器检查：桌面无顶部 header，390px 手机菜单可用；店名/Logo 的加载、失败、空 Logo 和长名称；11 语言中最长文案的布局；创建/编辑页与 Widget Studio 的主要交互回归。
- 构建与相关测试通过后仍需在获授权的开发店验证店铺名称、Logo 实际响应和嵌入式会话。独立原型截图不能替代真实 SHOPLINE 接入验收。
