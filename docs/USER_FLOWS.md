# User Flows

## 1. 创建活动

```text
Campaign list
  -> Create campaign
  -> 填写名称与商品范围
  -> 检查当前/即将生效活动的商品范围是否重叠
  -> 新增/编辑数量档位
  -> 选择店铺币种（默认）或已开通的市场金额模式
  -> 配置允许的折扣叠加意图
  -> 选择推荐档与时间
  -> Save draft 或 Publish
  -> 成功反馈
  -> Campaign list（状态为 Draft / Scheduled / Active）
```

校验：名称不能为空；至少一个档位；数量为唯一正整数；开始时间不得晚于结束时间；固定价格不得为负；推荐档只能有一个；与 Active 或即将 Active 的指定商品活动不存在商品范围交集；市场币种功能已经开通。分类活动之间以及分类与指定商品活动之间允许重叠，指定商品规则优先；多个分类规则的最终优先级由 SHOPLINE 处理。达到 4 件而最高已达档为 3 件时，全部 4 件按 3 件档计算。

### 折扣叠加与币种

```text
选择 Shop currency
  -> 商品折扣组合始终关闭
  -> 商家可分别选择 Order / shipping 组合意图
  -> 创建 Function 自动折扣时映射至 `DiscountAutomaticAppInput.combinesWith`

选择 Market-specific fixed amount
  -> 读取当前市场显示价格作为计算基准
  -> 所有组合开关锁定关闭
  -> 命中商品行不参与其他优惠、门槛或优惠分摊
```

## 2. 管理活动

```text
Campaign list
  -> 搜索 / 状态筛选 / 时间筛选
  -> 行菜单
     -> Edit -> 编辑页 -> Save
     -> Pause/Activate -> App Bridge 取消 / 确认 -> SHOPLINE 操作与回读确认 -> 刷新状态
     -> Delete -> 确认弹窗 -> 删除 -> 成功 toast
```

### 已失效活动重新发布（2026-11-18 用户确认）

```text
已失效活动 -> 明确启用，或编辑后保存
  -> 校验配置、订阅、覆盖范围与分类变量
  -> 为新活动生成独立 ID 并持久化候选配置
  -> 并行：删除旧 SHOPLINE 折扣 / 创建并核验新折扣
  -> 新建成功：新活动生效；未来开始则等待生效
  -> 删除确认成功：移除旧活动记录
  -> 删除失败或未确认：保留旧活动已失效，新活动独立生效
  -> 创建明确失败：保留原配置与失效结束时间供重试
  -> 创建结果不确定：保留新记录待核验，仅查询结果，不重复创建
  -> 已返回新 SHOPLINE ID 但尚未查到：最多查询 3 次，额外等待 300ms / 900ms
  -> 仍未确认：持久化该 ID，显示“已提交，正在确认活动启动结果”，不归入失败
  -> 列表自动只读核验最多 60 秒，确认后更新生效/等待生效并停止轮询
```

删除失败时，应用自己的活动列表也展示两条独立记录，分别关联旧、新 SHOPLINE 折扣 ID。旧活动保留原配置和实际结束时间，不能被新配置覆盖。后续查询确认旧折扣已不存在时，只移除旧活动，不能影响新活动。

已接收的新折扣 ID 在列表暂不可见时保持待核验，不因一次“查无记录”清除关联、降为草稿或重复创建。自动核验结束仍未知时保留该状态，后续进入/刷新可继续查询。SHOPLINE 查询返回限流或错误时不继续本次短重试，也不能把已接受的创建误报为创建被拒绝。

### 批量启用与订阅失效

```text
选择多个活动 -> Enable
  -> App Bridge 取消 / 确认
  -> 服务端逐项串行同步 SHOPLINE 状态并自动检查范围
  -> 指定商品交集或指定分类 ID 交集：该项保持暂停并返回活动名、冲突活动和重叠对象
  -> 其他项创建/恢复折扣并回读 ACTIVE
  -> 分别显示已启用、启动结果待确认与明确失败，合并提示以免相互覆盖

订阅确认失效
  -> 逐项删除应用创建的自动折扣并回读不存在
  -> 保留活动配置，清除旧折扣关联
  -> 续费后商家从列表明确 Enable
  -> 创建新的折扣并回读 ACTIVE
```

## 3. 商品页购买

```text
Product page
  -> Quantity Breaks widget
  -> 买家选择一个档位
  -> 当前选中档位卡片展开，并在卡内生成 N 个 Variant 槽位
  -> 买家为每件选择可售 Variant
  -> 合并相同 Variant 的数量并校验库存
  -> 原价、节省额、总价同步更新
  -> Add bundle to cart
  -> 显示本地演示成功或明确失败信息
```

正式实现时，Add to cart 必须由主题组件更新商品数量，并由 SHOPLINE 的优惠引擎返回最终价格。组件显示的预估价格不是结账权威值。

### Variant 槽位规则

```text
选择 3 件档
  -> slot 1 / slot 2 / slot 3 以默认可售 Variant 初始化
  -> 改变某个 option
  -> 仅可选择存在的组合
  -> 售罄组合不可选择；数量超过可用库存时阻断
  -> 切换至 2 件档：slot 3 草稿保留但隐藏
  -> 切回 3 件档：恢复 slot 3，重新检查其库存
```

若组合了相同 Variant，提交模型由槽位列表规约为按 `variantId` 分组的数量。例如 `[A, B, A]` 变为 `[{variantId: A, quantity: 2}, {variantId: B, quantity: 1}]`。选择器设为 Variant Image tiles 时，每个可售 Variant 显示其目录图片；售罄款式仍显示 `Sold out`，但不可选择。

## 4. 样式配置与预览

```text
Widget studio
  -> 修改文本、主色、背景、圆角或价格展示方式
  -> 预览即时变化
  -> 切换 desktop/mobile
  -> Save style
  -> 成功反馈（一期原型不持久化）
```

## 5. 本地化文案

```text
Widget studio
  -> Locale: 选择活动默认语言
  -> 在翻译列表中选择语言
  -> 编辑组件标题、档位优惠标签、价格汇总、购物车操作/反馈与规格选择的前台文案
  -> 查看 Complete / Missing 状态与实际 fallback 来源
  -> 在桌面 / 移动预览切换相同 locale
  -> Save translations
```

默认语言必须完整。其他语言可缺失并回退：精确 locale -> 店铺默认语言 -> 活动默认语言。`zh-CN` / `zh-SG` 使用 `zh-Hans`，`zh-TW` / `zh-HK` / `zh-MO` 使用 `zh-Hant`。

翻译页只展示当前店铺 app-block 使用的14项文案；组件说明、最高档位规则说明、通用税费/结账说明与 `Adding bundle...` 从编辑列表移除，历史已保存数据继续保留。`{quantity} items` 在活动没有自定义档位标题时用作标题，不代表每个档位始终显示该翻译。`Calculated at checkout` 仍用于无法计算金额时的提示，与已移除的通用结账说明不同。

翻译预览固定开启价格汇总、购物车规格明细和档位优惠标签，用于展示可选区域，不改变活动的实际开关。移除预览下方的独立文案示例区；标题、节省标签、原价、预计节省、组合总价与加购按钮这六项常驻文案不再显示用途说明，其余条件性文案保留说明。

商家可在“预览加购结果”中选择成功、失败、结果未确认或库存不足，再点击组件的加购按钮。按钮内先显示继承按钮文字颜色的旋转图标，随后在按钮正下方显示对应的本地化反馈，数量与购物车行数由当前选中规格生成。修改反馈翻译即时更新已显示结果；切换语言、商品或结果场景会取消未完成的模拟并清空旧反馈。预览不向真实购物车写入。

## 6. 空、加载和错误状态

| 场景 | 体验 |
| --- | --- |
| 无活动 | 简短说明 + Create campaign 主操作 |
| 列表加载 | 6 个固定高度 skeleton 行 |
| 筛选无结果 | 保留筛选条件 + Clear filters |
| 保存失败 | 字段错误优先；无法定位时展示可重试 toast |
| 无可用档位 | 组件不渲染，避免展示无法履约的优惠 |
| 已结束活动 | 管理端保留记录，商品端不渲染 |
| Variant 数据加载 | 槽位显示固定高度 skeleton，加入按钮禁用 |
| Variant 售罄 | option 显示 Sold out 并禁用，不自动替换买家已选值 |
| Variant 库存不足 | 汇总后指出对应规格与可售数量，阻止加购 |
| 原子加购失败 | 整套 Bundle 未加入；保留已选 Variant 并显示可重试的失败原因 |
| 加购接口明确拒绝库存不足 | 按钮下方显示 `widget.no_stock`；保留已选规格和数量，允许调整后手动重试，不自动再次加购 |
