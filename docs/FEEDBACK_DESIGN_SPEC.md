# 需求与建议 UI/UX 设计规范

**阶段：** 阶段 1 方案，尚未制作页面或截图。
**视觉基准：** `docs/reference/screenshots/shopify-roadmap-1037.jpg` 的多状态列、投票信息密度和加载骨架；实现必须遵循本项目的 Sea/Mint/Coral token，而不复制 Shopify/Kaching 品牌资产或样式。

## 设计原则

- 延续“精密零售运营台”：紧凑、可扫描、操作明确；不使用营销 hero、渐变装饰或嵌套卡片。
- 使用已有 token：Ink `#102A2A`、Sea `#0F766E`、Mint `#DDF6EF`、Coral `#C6492D`、Amber `#A16207`、Line `#D9E0DC`；控件 6px、面板 8px、4px 间距基线。
- 沿用应用根部的 Inter 字体栈和现有 CSS Modules。通用 UI 建议工具仅贡献交互准则，不覆盖项目设计令牌。
- 每个状态同时有文字和颜色；图标来自已安装的 `lucide-react`，图标按钮必须有 `aria-label` 和 `title`。

## 页面结构（桌面）

```text
页面标题“需求与建议”                                   [建议]
帮助说明：提交改进建议，投票帮助确定优先级

[ 搜索建议 ................................ ] [状态 v] [最新发布 v]

建议列表 / 以票数排序
┌───────────────────────────────────────────────────────────┐
│ 状态徽章  标题                              [投票 12]      │
│ 摘要最多两行，超出省略                                      │
│ 商家提交 · 2026-10-29 · 官方已回复                         │
└───────────────────────────────────────────────────────────┘
                                                [上一页] [下一页]
```

参考截图中的多列 Roadmap 是可用的信息组织参考，但本期五个状态在 1037px 下不应强塞为五列。默认使用可筛选的单列表，在宽屏（>=1200px）可按状态分成横向滚动的列视图作为后续增强，前提是视觉验证证明内容不被裁切。这样能保住搜索、长标题、移动阅读和键盘顺序。

## 组件规格

| 组件 | 设计与交互 |
| --- | --- |
| `FeedbackPageHeader` | 标题 28px/34px，副说明 14px/20px；Sea 主按钮文字固定为“建议”，点击打开提交弹窗。 |
| `FeedbackToolbar` | 搜索、状态 `select`、排序 `select`。输入有可见标签或 `sr-only` 标签；操作区在小屏可换行。 |
| `FeedbackCard` | 单层白色表面、1px Line 边框、8px 圆角；整卡详情链接不能嵌套可点击投票按钮。 |
| `FeedbackStatusBadge` | 待定灰/Ink，已批准 Sea/Mint，开发中 Amber，已上线 Sea，已拒绝 Coral 的低饱和表面；始终含中文状态文本。 |
| `VoteButton` | 固定最小宽度，未投票为次级边框按钮，已投票为 Mint 填充；`aria-pressed` 与禁用加载态。 |
| `SubmitFeedbackDialog` | 对话框用现有确认框模式；标题、内容、字符计数、类似建议区域、错误摘要，以及“取消”“提交”两个操作。相似结果区域最小高度 96px，避免请求返回时跳动。提交成功后关闭弹窗并调用现有 App Bridge success message，不渲染本地成功 toast。 |
| `FeedbackDetail` | 返回链接、完整正文、状态时间线、官方回复；时间线按 DOM 顺序从新到旧或旧到新保持一致，推荐旧到新。 |

## 响应式与可访问性

| 断点 | 规则 |
| --- | --- |
| >= 1200px | 内容最大宽度与现有工作区一致；投票操作靠右对齐。 |
| 768--1199px | 工具栏允许换行；卡片保持两列信息（内容/操作）。 |
| < 768px | 工具栏单列，投票移至卡片底部全宽或不小于 44px 的按钮；摘要和元数据不横向溢出。 |

- 键盘焦点为现有 2px Sea 外环；对话框需焦点陷阱、Esc 关闭和关闭后返回触发按钮。
- 表单错误摘要 `role=alert` 且可聚焦；字段错误通过 `aria-describedby` 关联。
- `aria-live=polite` 只通告提交/投票结果，不对每次搜索输入朗读。
- 遵守 `prefers-reduced-motion`；搜索/投票没有非必要连续动画。
- 阶段 2 完成后必须保存桌面（1037px）和移动（390px）参考对照与本地截图；本阶段不得把视觉验收标记为已通过。

## 文案规范

- 页面：需求与建议；入口操作：建议；弹窗操作：取消、提交；列表作者：商家提交；回复标签：官方回复。
- 用动词描述动作：投票、取消投票、查看详情、提交建议、重试。
- 不在商家界面显示“管理员”“shop_id”“内部审计”或隐藏原因。
- 新键必须覆盖当前 11 个应用 locale；缺失翻译不能回退为裸 key。
