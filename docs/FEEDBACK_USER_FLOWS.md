# 需求与建议用户流程

**阶段：** 设计，尚未实现。所有流程假定已验证的嵌入式 SHOPLINE 会话。

## 商家信息架构

```text
/quantity-breaks/feedback
  ├─ 列表：搜索、状态筛选、排序、分页、投票
  ├─ 提交建议对话框：相似建议、字段校验、提交
  └─ /quantity-breaks/feedback/:id
       ├─ 完整建议、状态时间线、官方回复
       └─ 当前店铺的投票状态
```

侧栏或现有应用导航增加“需求与建议”入口；不创建独立营销页，也不更改应用名称。

## 1. 浏览、搜索和详情

1. 商家进入列表，先显示固定高度 skeleton，随后读取第一页 `sort=newest` 数据。
2. 商家选择状态、排序或搜索。搜索输入使用延迟值，最少 2 个字符后请求；筛选变化重置游标。
3. 卡片或表格行显示状态徽章、标题、两行摘要、日期、票数、是否已投票和是否有官方回复。
4. 商家点击行进入详情；浏览器返回键回到保留查询参数的列表。
5. 若目标已隐藏或不存在，显示现有 Not Found 状态，不透露隐藏事实。

## 2. 提交建议与相似推荐

1. 商家点击“建议”按钮，打开对话框，焦点落在标题。弹窗只提供标题、内容、取消和提交操作；相似建议是表单辅助区，不新增额外操作按钮。
2. 在标题停止输入 300--500ms 后，若至少 3 个非空白字符，读取最多 5 条相似公开建议。
3. 相似区预留稳定位置：加载时 skeleton，结果显示标题、状态、票数、详情和投票入口；无结果不强行阻止提交。
4. 商家填写标题与内容。失焦后展示字段错误；提交失败时，将焦点移至含链接的错误摘要，仍保留输入值。
5. 提交按钮生成一次性 `Idempotency-Key` 并禁用至完成。成功后关闭对话框，通过现有 App Bridge 显示“提交成功”，将新建议插入列表顶部并导航到详情；网络重试使用同一键。
6. 服务端返回重复提交时，保留内容并提示“已存在相同建议”，提供现有详情入口；商家可返回编辑而非被静默丢弃。

## 3. 投票

1. 未投票按钮为“投票”，包含当前票数；已投票为“已投票”，`aria-pressed=true`。
2. 点击后局部乐观更新，控制尺寸固定，防止数字变化挤动卡片。
3. 请求成功以服务端返回状态收敛；请求失败回滚、显示可重试 toast，并把焦点保留在按钮。
4. 已隐藏或刚被管理员隐藏的建议投票返回 `404`；客户端移除该项目并提示内容不可用。

## 4. 详情状态与官方回复

1. 顶部显示当前状态的文本+颜色徽章与投票操作。
2. 时间线只展示公开字段：状态、时间、可选公开备注；不展示 `admin_id`、店铺身份或内部隐藏动作。
3. 官方回复按创建时间升序显示，明确标注“官方回复”；被隐藏回复完全不返回。
4. 无回复、加载失败和空时间线各有独立文字状态，不以空白区域代替。

## 5. 开发者管理 API 使用流

1. 未来 Developer Admin Console 取得其身份提供方签发的服务端 token，并在网关处解析出 `adminId` 与 `feedback:read`/`feedback:write` 权限。
2. 网关调用 Worker 内部接口，携带签名、时间戳、nonce 和可信管理员声明；Worker 验证请求未被重放、管理员存在且拥有对应角色。
3. 状态、可见性和回复变更先写业务记录和审计日志，再返回最新资源；状态变更同时生成商家可见历史。

## 状态矩阵

| 场景 | UI 行为 | API 行为 |
| --- | --- | --- |
| 未认证/会话失效 | 使用既有重新授权流程 | `401 AUTH_REQUIRED` |
| 未安装店铺 | 不显示数据 | `403 STORE_NOT_ACTIVE` |
| 提交超限 | 保留表单内容并显示重试时间 | `429 RATE_LIMITED` + `Retry-After` |
| 字段不合法 | 就地错误+错误摘要 | `422 VALIDATION_ERROR` |
| 相似搜索无结果 | 说明未发现相似建议 | `200 items=[]` |
| 隐藏/不存在详情 | 通用 Not Found | `404 NOT_FOUND` |
| 管理员权限不足 | Developer Console 拒绝操作 | `403 ADMIN_FORBIDDEN` |
