## 一次只处理一个区域的视觉执行计划

此计划只用于等待确认后的 UI 工作，不是 SHOPLINE API/Function 的正式开发计划。每批完成后展示截图、交互结果、改动文件与测试，再单独取得下一批确认。遵循 Superpowers 的小范围实施和验证原则。

1. **P0 首页内容区**：把概览与活动管理合成一个可扫描页面；确定哪些参考指标适用于一期，保留原有创建、搜索、筛选、启停、编辑、删除入口。验收：桌面 tab/搜索/行操作可用，状态不丢失。
2. **P0 活动编辑区**：按参考的产品、设置、样式、档位、预览顺序整理折叠结构；创建与编辑共享实时预览。验收：现有商品冲突、日期、叠加提示和 Variant 设置仍可访问，未修改正式业务逻辑。
3. **P0 档位区**：逐档整合数量、价格类型、标题、副标题、标签、默认选中；检查任意正整数与文案长度。折扣计算变更需在正式业务计划中另行设计与批准。
4. **P1 应用视觉 token 与导航**：黑白灰为主，蓝色滑块/焦点强调；区分 SHOPLINE 容器与应用自绘部分。保留商家店铺名称/图标，不使用 Kaching 专有资产。
5. **P1 前台组件**：在固定桌面宽度和 390px 手机宽度核对档位尺寸、字级、推荐标签、价格与选中边框；内外圆角一致，缺货/多规格保持本项目已有语义。
6. **P2/P3 状态与响应式**：逐个验证 hover/focus/disabled/loading、空/错误/成功、长翻译、不同 SKU 价格、售罄库存、360/390/768/1440px。参考未覆盖的状态要用本项目需求验收，不能冒称参考产品行为。

## 阻塞与需确认项

- 用户早期要求不照搬品牌视觉/专有素材，当前又要求高保真；执行时只参照布局、密度、状态与测得规格，不复制 Kaching 图标、文案或源代码。
- 参考前台商品没有可观察的独立 Variant 选择器。若该区域也要求逐像素对照，需要可切换款式且含售罄状态的参考页面或截图。
- 原型目前由本地 mock 驱动；UI 验收不等于 SHOPLINE 真实折扣/加购验证。正式 API、Function、数据库与结账实现仍应在 UI 确认后的另一期计划中处理。
