## 使用者与成功标准

主要使用者是中小型 DTC 商家的运营人员：他们需要在几分钟内创建可解释、可预览、可停用的多件活动，而不是学习复杂的促销规则。

成功标准：

- 商家可创建、编辑、启停和删除活动。
- 每个活动可配置多个数量阶梯与一个默认推荐档位。
- 商品详情页组件清楚显示单价、原价、节省金额与推荐标签。
- 活动按开始/结束时间显示状态；无结束时间表示持续生效。
- PC 与移动端均可预览组件效果。
- 原型中的状态、反馈和错误均可被体验；不调用 SHOPLINE。

## 功能需求

### 活动管理

- 创建请求返回新 SHOPLINE 折扣 ID 后只重试查询确认，不重发创建；查询延迟可在 300ms、900ms 后再查。仍无法确认时保存该 ID 为待核验，单条/批量启动及编辑已失效活动保存应显示“正在确认活动启动结果”，不得计作明确失败或提前显示生效。活动列表自动只读核验最多 60 秒，前 10 秒约每 2 秒、之后约每 5 秒，确认后停止；离开列表或切换店铺时取消本轮定时器，超时继续保留待核验，后续进入/刷新仍可核验。批量成功、待确认、明确失败分别反馈，不相互覆盖；待确认活动仍占用已提交的商品覆盖范围，阻止同一批创建重叠活动。删除与创建继续并行，删除失败保留旧活动已失效，新活动确认成功后独立生效。
- 创建、编辑、删除、启用/停用 Quantity Breaks 活动。
- 列表包含名称、覆盖商品、档位、状态、排期、最近更新与操作。
- 支持按名称搜索，按状态和时间筛选。
- 状态：Draft、Scheduled、Active、Paused、Ended。状态是 `enabled`、`startsAt`、`endsAt` 的派生视图。
- 删除需要二次确认；停用可即时完成，并给出可撤销反馈。

### 阶梯与价格

- 一个活动至少一个数量阶梯；数量为正整数且不可重复。
- 折扣策略：百分比折扣、每件固定金额减免、每件固定价格、整单固定金额减免、整单固定价格。
- 每档可设置名称、促销标签、推荐标记和排序。
- 已确认产品规则：达到任一档位后，使用“最高已达档”的每件价格/折扣计算全部数量。因此 2 / 3 / 5 件档位下购买 4 件时，4 件全部按 3 件档结算。商家可以配置任意正整数数量档位。
- 金额计算使用最小货币单位整数；展示时按商店货币的小数位格式化。百分比内部使用基点（例如 10% = 1000 bps）；中间计算不得使用浮点数。

计算定义（`p`=原单价最小货币单位，`q`=数量）：

| 类型 | 每件最终价 `u` | 总价 `q*u` |
| --- | --- | --- |
| percentage | `round(p * (10000 - bps) / 10000)` | `q*u` |
| fixed_amount | `max(0, p - amount)` | `q*u` |
| fixed_price | `price` | `q*u` |

整单金额型折扣按同一 Product 的命中购物车行合计计算，令 `S` 为该商品所有命中行的原价合计：

| 类型 | 商品组合计最终价 |
| --- | --- |
| bundle_fixed_amount | `max(0, S - amount)` |
| bundle_fixed_price | `min(S, price)` |

Function 对整单类型必须返回折扣级 `fixedAmount` 或 `presentmentFixedAmount`，并设置 `appliesToEachItem=false`；targets 只包含该 Product 的命中行，平台在这些行内分摊金额。每件固定类型继续为每条命中购物车行返回 `appliesToEachItem=true` 的金额。

舍入模式、税前/税后基准和多币种换汇权威来源留待技术设计确认。

`fixed_price` 不是 Product Discount Function 的原生 Output 类型。正式实现需对每条命中 cart line 计算 `max(0, 原单价 - 固定单价)`，再返回该行的 `fixedAmount` 或 `presentmentFixedAmount`；不能把固定单价作为虚构的 Function 字段提交。

### 商品范围

- 指定商品分类的动态 Shop 配置固定使用 `$app:quantity-breaks` / `collection-membership`、JSON `inCollections`。元字段及元字段定义请求的 `owner_resource` 均固定填写小写 `shop`；定义权限显式为 `access.admin: MERCHANT_READ`。同步分类配置时检查定义，缺失则创建，权限不符则原位更新并回读确认；不得仅向元字段值添加 `access`，也不得因定义更新而替换分类 ID。权限未确认时阻止后续折扣发布并保留诊断响应及 TraceID。
- 选择方式：全部商品、指定商品、指定商品分类、排除指定商品。
- 一期计数范围固定为“同一个商品的累计购买数量”；不同商品不合并计数。
- 当范围冲突时，排除规则优先于包含规则。这是应用内编排规则，仍须验证能否无损映射至 SHOPLINE 的原生优惠模型。
- 编辑页的“检查商品覆盖范围”是预览工具；单个及批量启用必须在服务端自动复查，不能要求商家先手动执行。
- 指定商品对指定商品：Product ID 有交集时冲突。指定分类对指定分类：分类 ID 有交集时冲突，冲突结果必须列出两个活动名称和重叠分类标题。指定分类对指定商品不检查覆盖范围，也不阻止启用。
- 批量启用时，冲突项保持未启用，其余无冲突项继续处理；“已启用”计数只能统计 SHOPLINE 回读确认为 `ACTIVE` 的活动。
- 分类冲突按分类对象 ID 判定，不按分类成员商品的实时展开结果判定。

### 平台状态与订阅

- Function 折扣删除固定使用 `DELETE /admin/openapi/v20261201/sales/discount_apps/{function_id}/{app_discount_id}.json`；适用于商家删除、失效活动替换、管理后台删除及订阅到期清理，不回退到无版本路径。返回成功后仍须查询确认折扣不存在，诊断记录保留实际版本路径及 SHOPLINE TraceID。
- SHOPLINE 自动折扣状态是运行时权威来源。D1 仅保存活动配置、关联折扣 ID、最后核验时间和操作状态；列表、详情及启用/暂停前都要同步实际状态。
- 停止请求尚未由 SHOPLINE 确认时保持处理中；平台确认 `expired/inactive` 后，保留配置并记录结束时间。商家明确重新启用已失效活动，或编辑已失效活动后点击保存时，删除旧 SHOPLINE 折扣与创建新折扣并行执行，分别处理结果。新折扣对应独立的应用活动 ID；按原配置或本次提交配置发布，未来开始时间等待生效。删除被拒绝、超时或回读仍存在时，不阻止新折扣生效，应用列表同时显示旧活动已失效与新活动生效/等待生效。删除回读确认缺失且新记录已保留后才移除旧活动记录。
- 订阅确认失效（`inactive`、`expired` 或 `cancelled` 的最终失效结论）时，删除应用创建的自动折扣。删除回读确认缺失后，保留活动配置，标记为订阅失效并清除折扣关联；续费后只能由商家明确启用，创建新的自动折扣。
- 订阅失效导致折扣删除、且 SHOPLINE 已确认缺失时，活动的 `endsAt` 直接写为确认失效的时刻，`neverExpires` 设为 `false`。列表结束时间按店铺时区显示；重复任务不改写首次记录，删除失败或结果未核实不得提前写入。历史记录仅凭同店铺、同活动已保存的删除确认时间回填，不使用迁移执行时间猜测。
- 结束时间规则同时覆盖平台直接返回失效、主动停止确认、平台折扣删除及订阅失效。平台失效优先采用有效且已到达的 SHOPLINE `ends_at`；未提供时保留已记录的过去结束时间，否则记录本次确认失效时间。重复核验不得用当前查询时间不断覆盖；已存在的失效活动在下一次成功核验时补齐结束时间。
- 已失效活动编辑后重新发布时，结束时间早于或等于当前时间须在删除旧折扣、创建新折扣之前拦截，提示“当前结束时间早于当前时间”。若 SHOPLINE 返回 `endAt is illegal, endAt before now`，同样显示该中文提示，诊断中保留原始响应及 TraceID；其他 422 原因不得误报为结束时间错误。
- 新旧活动各自持久化配置、结束时间、平台折扣关联及发布状态。创建明确失败时保留原失效活动供重试，不留虚假的生效记录；已确认删除则清除旧关联。创建结果不确定时保留新 ID 与候选配置并显示待核验，按新 ID 的规则元字段只读核对，不重复创建，不把旧折扣重新关联给新活动。并发读不得清除正在执行的发布锁；执行中断后租约到期仅核对结果。
- 续费不会自动重新发布；商家明确启用时重新校验覆盖范围，成功创建新的自动折扣后才清除旧失效结束时间、恢复持续生效。创建失败或对账未找到新折扣时保留原失效记录。
- 生效活动更新为指定分类时，服务端须重新分页读取分类成员并生成可信 `resolvedProductIds`，不依赖编辑器上传的商品快照；发布前同步旧、新及其他活动需要的分类 ID 并集，平台确认更新后收敛。元字段清理失败保留安全超集并记录诊断，不将已确认的更新误报失败。
- 活动页使用店铺的 `iana_timezone` 显示当前套餐到期时间及已核实的下一期套餐生效时间，并提供 SHOPLINE App Bridge 原生套餐购买入口。若当前套餐剩余不超过 7 天且没有可衔接的有效下一期套餐（包括两期之间存在空档），提示到期后折扣失效；自动续费标志本身不作为隐藏该提示的依据。
- 下一期展示依据订阅列表：同店铺、`ultra`、`active / preorder`、未来开始且结束晚于开始，取最早一期；展示不要求该期详情具有 `quantity_breaks_access`。展示时间以独立的 `nextDisplayFrom/nextDisplayUntil` 保存，不能用于访问授权或折扣失效判定；原 `nextValidFrom/nextValidUntil` 继续仅保存功能点已核验的续接权益。连续下一期到期/生效时间同行显示、不插入强制换行，窄屏空间不足时自然换行，且不显示失效文案；有空档并临近到期时仍提示风险，取消下一期后清除对应展示时间。
- 每店铺的批量活动逐项串行执行；同一失效活动重新发布内部的旧折扣删除与新折扣创建并行。遇到 HTTP `429` 时尊重 SHOPLINE 的 `Retry-After`，且不得假定固定 QPS。

### 币种与叠加

- 默认以店铺币种计算，Function 使用 `fixedAmount` 或顶层 `percentage` 返回商品折扣。
- 白名单已开通。商家可为指定 `marketId` 配置市场固定金额/固定单价；Function 必须读取当前市场显示价格并使用 `presentmentFixedAmount`，币种必须等于当前购物车市场币种。
- Market-specific mode 需要明确的“不可与其他优惠叠加”提示和锁定的开关。用户资料确认，命中 `presentmentFixedAmount` 的商品行不参与其他 Function、主站或插件活动，也不参与其他折扣的门槛计算或优惠分摊。
- 本应用的商品折扣一律不与其他商品折扣叠加。官方文档确认创建 Function 自动折扣时可通过 `DiscountAutomaticAppInput.combinesWith` 声明可叠加的折扣层级：在店铺币种模式，商家可分别选择是否与订单折扣、运费折扣叠加；市场币种模式不得展示为可选，因为 `presentmentFixedAmount` 命中行的强制排他规则优先。
- Product Discount Function 本身只产生商品折扣，不能创建订单维度折扣或免运费折扣。

### 商品页组件

- 显示标题、可选说明、多档选择卡、标签、原价/优惠价/节省额、总价和加入购物车。
- 选择档位时，价格、选中态和总价即时更新；推荐档默认选中。
- 组件需支持键盘操作、可见焦点、语义化单选组、色彩不作为唯一状态信号。
- 组件样式可配置，配置变更即时反映在桌面与移动预览。

### 同商品 Variant 混购

- 一期新增“同一 Product 下不同 Variant 混合计数”。活动命中按合格购物车行中属于同一 Product 的 Variant 数量总和计算，不跨 Product 汇总。
- 买家选择数量档位后，组件按该数量生成独立的选择槽位。例如选择 3 件，显示 3 个 Variant 选择器；每一槽位可选择不同规格。
- 规格 UI 必须从商品实际 `options` 和 `variants` 数据生成，不能假定只有颜色、尺码或任何固定 option 名称。展示形态可为 Dropdown、Buttons、Swatches 或 Variant Image tiles；Image tiles 使用该 Variant 的商品目录图片。
- 无效 option 组合必须禁用；不可售/无库存 Variant 显示“Sold out”并不得加入 bundle。库存低于当前同 Variant 已选数量时，显示可售数量和阻断性错误。
- Variant 价格可以不同。预览原价为所有已选 Variant 的原价之和；阶梯命中使用所有槽位的总数量；折扣以活动配置计算。前端的结果是预估，平台结账结果才是权威。
- 相同 Variant 在多个槽位被选择时，加入购物车请求要合并为一个 Variant ID 加数量；不同 Variant 保持独立购物车行。
- 切换档位时，保留已填写槽位；低档位隐藏而不清除额外槽位草稿，后续切回高档位时恢复。若原选择已不可售，要标记为需重新选择。
- 默认选择策略提供“第一个可售 Variant”或“要求买家选择”。推荐一期默认“第一个可售 Variant”，并清晰可编辑。

### 加入购物车

- 点击 `Add bundle to cart` 前，验证档位、每个槽位的完整选择、Variant 存在性、可售状态及按 Variant 汇总后的库存。
- 构造 `[{ variantId, quantity }]`，同 ID 合并后再交给购物车接口；绝不把不同 Variant 折叠成任意一个 SKU。
- 购物车已确认支持原子批量加购。主题端应将相同 Variant 合并后一次提交；请求失败时整套 Bundle 保持未加入状态并显示可恢复错误，不需要逐行部分成功路径。
- 原型仅模拟成功、加载、库存不足和加入失败反馈，不发送购物车请求。

#### 真实主题 app-block 的可售与价格展示规则（2026-11-19 更新）

- 商品 `product.available=false` 时，真实主题不输出整个组件；脚本收到商品不可售标记时也保持隐藏，并且不请求活动数据。商品可售时再按原有活动、订阅和范围规则判断是否展示。
- 真实主题组件以款式 `available` 为唯一可售依据：`true` 允许选择和提交加购，`false` 显示缺货并禁用加购。默认款式、选择器缺货标记、汇总和按钮使用同一判断。
- 商品可售但所选款式不可售时，组件仍显示，加购按钮显示本地化 Sold out 并禁用；切回可售款式后恢复。
- 档位标题、每件款式价格和购物车款式明细中，原价与折后价按货币最小单位比较；仅有实际优惠时输出划线原价，相等时只输出折后价，包括零金额及舍入后相等的情况。
- 档位售价使用 `span.qb-tier-price`，独立应用活动设置的售价字号、字重和颜色，避免 `<b>` 默认 bolder 造成字重偏差。
- 本规则覆盖上述原型的库存数量校验要求在真实 app-block 中的应用：不依赖库存追踪、超卖策略或库存数量推断，不按累计数量在组件中阻断；相同款式仍合并数量，最终库存限制由 SHOPLINE 加购/结账接口校验。原型预览本次不变更。
- 全部款式不可售时仍保留组件及档位，禁用加购并显示售罄。SHOPLINE 加购请求失败时显示失败反馈，不报成功。
- 页面加载时可售但加购时库存不足：若 SHOPLINE 响应明确返回 `message: Out of stock` 或 `description: stock not enough`，使用 `widget.no_stock` 本地化反馈。保留已选规格与数量，不自动重试加购；其他失败沿用通用失败或结果待确认反馈。
- 真实 app-block 加购过程中在按钮内显示 20×20 的 `loading--rotator` SVG，描边使用 `currentColor` 继承按钮文字颜色；不再显示 `Adding bundle...`。加载时禁用按钮并标记 `aria-busy`，档位/视口重渲染不能恢复加购按钮或重复提交；结束后恢复正常按钮文字，反馈仍在按钮下方。尊重减少动态效果偏好。

### 样式配置

- 主题强调色、卡片背景、选中态、边框、圆角、标题、说明、推荐标签和价格展示方式。
- 提供桌面及移动模拟预览，移动以 390px 画布呈现。
- 配置页需要显示保存中、保存成功、无法保存等状态；一期仅模拟这些状态。
- 新增：Show variant selectors、Variant selector style（Dropdown / Buttons / Swatches / Image tiles）、Default variant selection、Show stock status、Show original and discounted price。不同 Variant 固定允许合并计数，不提供关闭开关。Image tiles 需可配置图片尺寸、圆角与是否显示 Color 色值；Widget 字号支持任意正整数 px，PC 与移动端均不再限制为 5–20px 或 5–28px；旧 bodyPx 字段保持相同规则。纯文本选择器只对缺货值显示 Sold out；图片款式以禁用和降低透明度表达缺货。

- “预计节省标题”和“预计节省金额”分别提供字号与粗细设置，PC / 移动端独立，预览与 app-block 使用相同配置。旧配置缺少标题字体时默认 11px / 400，金额字体不受影响。
- 商品页区域标题优先使用已保存的前台翻译；未配置时使用主题当前语言的默认标题（最终回退 Bundle & save），商家显式保存空标题时隐藏。不使用活动内部名称作为默认区域标题。

### 多语言与本地化

- 商家后台 UI 和商品页 Widget 必须支持：English (`en`)、French (`fr`)、German (`de`)、Spanish (`es`)、Italian (`it`)、Dutch (`nl`)、Swedish (`sv`)、Turkish (`tr`)、Portuguese - Brazil (`pt-BR`)、Simplified Chinese (`zh-Hans`) 与 Traditional Chinese (`zh-Hant`)。
- Widget 的可翻译内容包括标题、说明、档位名称、促销标签、价格摘要、库存文案、加入购物车、加载、错误和成功反馈。商品本身的 title、Option 名称和值由商品目录/主题提供，本应用不得自行翻译或覆盖。
- 活动需要保存默认语言文案和可选翻译集。只有默认语言为必填；未提供的语言按“精确 locale -> 店铺默认语言 -> 活动默认语言”回退，并在编辑器中标记为 Missing translation。
- 输入 locale 必须标准化：`zh-CN`、`zh-SG` 映射至 `zh-Hans`；`zh-TW`、`zh-HK`、`zh-MO` 映射至 `zh-Hant`。`pt` 不得自动等同于 `pt-BR`，除非店铺明确选择 `pt-BR` 为回退语言。
- 金额、日期和数量必须使用当前 locale 格式化；金额币种及权威价格仍来自 SHOPLINE 的当前店铺/市场数据，翻译层不可换算金额。
- Function 规则、活动范围、数量计算和折扣金额不依赖显示语言。语言内容的更新不得改变已发布活动的计算结果。

## 非功能要求

- React、TypeScript、Tailwind CSS、可复用组件边界。
- 桌面端最小支持 1024px；移动端最小支持 360px。文字不得裁切或重叠。
- 关键操作使用可访问名称；焦点环可见；错误与成功反馈使用 `aria-live`。
- 原型内不保存账号、店铺、token 或真实商品数据。
- 原型中的英文文案只表示 default locale；正式 Widget 不得把英文硬编码为唯一可见语言。
